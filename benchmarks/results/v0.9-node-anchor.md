# V0.9 — NodeAnchor vs 旧 tree 路径

三种策略的快路径相同（FTS + Vector，bge-small），区别只在 tree 的结果怎么进入上下文：

- `policy_hybrid`：不开 tree。
- `anchor_hybrid_full_blocks`：开 tree，走 V0.9 之前的路径。LLM 选中一节后，用 FTS 在节内取几块。
- `anchor_hybrid_full_node`：开 tree，走 V0.9 的 NodeAnchor。LLM 选中的整节作为一个锚点，接管本节内排名最高的快路径块，上下文围绕该块在本节（子树）范围内展开。

两种 tree 策略都设 tree 权重 0.5、`agentic_level=1.0`（tree 每题都跑），最多 6 步、6 次 LLM 调用。QA 由 DeepSeek 作答并判分，用 auto 上下文，每个配置独立跑两轮。FinanceBench 用 hybrid 结构。原始报告：`v0.9-qa-anchor-*.md`。

本报告是修复「吸收必须在候选池截断之前」之后重跑的结果（见 `docs/v0.9-architecture.md`）。修复前 node 模式几乎不起作用：20 题里只有 2 题留下了 NodeAnchor，那一轮作废。

| 数据集 | 预算 | 不开 tree | node | blocks | node 对不开 tree | node 对 blocks | blocks 对不开 tree |
|---|---|---|---|---|---|---|---|
| longdoc（91） | @1000 | 58.2 | 55.5 | 57.1 | 6:11，p=0.33 | 3:6，p=0.51 | 9:11，p=0.82 |

## 结论

- **NodeAnchor 在两个数据集、@2000 预算下都不差于旧 tree 路径，多数配置更好。**
  - longdoc 上 node 对不开 tree 7:0（p=0.016），两轮都赢（70.3、69.2 对 65.9、65.9）。
  - FinanceBench 上 node 对 blocks 13:4（p=0.049）。
  - 原因：旧路径塞进来的是「节内 FTS 的几块」，零散，还会挤掉快路径的命中，所以 FinanceBench 上 blocks 对不开 tree 是 3:10。NodeAnchor 让快路径命中保持原位，再把它周围的本节内容一起读进来。
- **注意多重比较和噪声。**
  - 这里一共做了 12 次检验，p≈0.05 的结果单独看并不可靠。
  - 同一份不开 tree 的代码，在同期 graph 实验里的 longdoc @2000 是 68.1 / 70.3，在这里是 65.9 / 65.9。把四轮放在一起算，不开 tree 是 67.6，node 是 69.8，差距约 2 分，而不是表里的 4 分。
- **@1000 时 tree 没有帮助。** node 55.5、blocks 57.1，不开 tree 58.2。预算太紧时，整节内容会占掉其他命中的位置。
- **成本**：每题多约 3k 导航 token、最多 6 次 LLM 调用。
- **建议**：
  - `tree_anchor="node"` 保留为 tree 开启时的默认读法，它明显优于旧路径。
  - tree 本身仍默认关闭（`tree_weight=0`），这与 V0.6 权重扫描的结论一致。只有预算 ≥ 2000、愿意付导航成本时，才值得开 tree。
