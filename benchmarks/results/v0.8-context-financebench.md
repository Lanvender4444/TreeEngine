# V0.8 — Context & QA on FinanceBench (V0.7 vs V0.8 heading rules)

`run_qa --suite financebench --strategies fts+vector --embedder fastembed:BAAI/bge-small-en-v1.5 --pdf-structure {hybrid,layout} --context section600,auto --budget 1000,2000`. 150 questions, DeepSeek answer + judge, two independent runs per version. V0.7 = the same code with the V0.7 `pdf/headings.py` and `pdf/validate.py`. Retrieval is identical in both versions (same blocks, same FTS / vector results), so only the section boundaries that `section600` / `auto` read inside differ.

`auto` at a 1,000-token budget resolves to `section600`; the two rows differ only by LLM sampling.

Noise floor: rerunning the *same* code flips 11–20 of 600 verdicts (V0.7 hybrid 20, layout 18; V0.8 hybrid 15, layout 11); V0.7 → V0.8 on hybrid run 1 flips 22. The version effect is not distinguishable from LLM sampling.

## Reading

- Fewer false headings → slightly larger sections: section600 spans grow 2–6% and cross fewer section boundaries (layout @2000 0.41 → 0.33), as intended.
- At a tight budget the larger spans cost a little evidence coverage (@1000: hybrid 38.7 → 38.0, layout 39.0 → 37.7); at @2000 coverage is unchanged.
- QA: no measurable change in either direction. Structure precision only reaches the answer through section boundaries now (V0.7 made retrieval tree-independent), and on FinanceBench that channel is narrow.
