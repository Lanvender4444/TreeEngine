# V0.16 — 参考路线统一评测：Reranker、表格解析、上下文索引、自检重试、提示词优化、Evidence Search（MCTS）

设计说明见 `docs/v0.16-evidence-search.md`。所有参数只在 dev 上确定；held-out 上只运行最终候选，各跑 2 轮。

## 0. 评测设置

- **dev**：FinanceBench / longdoc / multires2 的哈希切分 dev（35 / 23 / 20 题），用于短测和选型。
- **held-out 1**：FinanceBench 哈希切分 test，115 题。
- **held-out 2**：**finx**，全新留出集，116 题，V0.16 新建。
  - 来源是 FinanceBench 开源集（patronus-ai/financebench@cc39aeb）里此前从未用过的 24 份 PDF：69 道指标题、47 道领域题。
  - 每道题都经过两项核对：能从标注页面答出，闭卷答不出。
  - 构建脚本：`benchmarks/datasets/finx/build.py`。
- 每题证据预算 2000 token。判分规则同前：先精确匹配，不匹配再用 LLM 判语义是否一致。
- 胜:负 = 两轮逐题合计，p 为双侧符号检验。

### 1.4 表格感知解析 + 上下文索引

FinanceBench dev，35 题，1 轮。TC 语料 = `--pdf-tables --index-title context`：表格区域合成一块，并加上“文档 | 章节 | 页标题”的上下文索引。两项是一起开的，没有分别消融。
- 基础语料：84 份文档，平均每块 484 字符。
- TC 语料：只入库 dev 题用到的 26 份文档，平均每块 560 字符，其中 379 个表格块。

| 方案 | 基础语料 | TC 语料 | 逐题 胜:负 |
|---|---|---|---|
| auto | 40.0 | 40.0 | 3:3 |
| gate | 54.3 | **71.4** | 8:2 |
| gate+retry | 71.4 | **80.0** | 5:2 |
| reranker 特征 + gate | 65.7 | 71.4 | 3:1 |
| reranker 特征 + gate+retry | 71.4 | **80.0** | 4:1 |
| search_fill | 34.3 | 34.3 | 2:2 |
| search_prior | 37.1 | 40.0 | 3:2 |

- 在 dev 上，TC 语料对所有 LLM 选读方案都有提升，合计 20:6。
- 对零 LLM 的 auto 和 Evidence Search 没有影响。
- 推测原因：完整的表格块更容易被 LLM 选中，读起来也更完整；但它并没有让 FTS / 向量 / reranker 的排名本身变好。
- **这一结论只在 dev 上得到**：finx 的 TC 语料因为时间不够没有构建，所以没有 held-out 验证，列为下一步。

### dev 结论 → 进入 held-out 的候选
- `gate`（V0.15，对照）、`auto`（零 LLM 对照）；
- `gate+retry`；

## 2. held-out 结果（2 轮）

准确率列为“第 1 轮 / 第 2 轮（平均）”；胜:负为对 V0.15 `gate`、两轮逐题合计。

| 方案 | FinanceBench test（115） | 胜:负 | **finx（116，全新）** | 胜:负 | 合并 胜:负 | p |
|---|---|---|---|---|---|---|
| auto（零 LLM） | 42.6 / 42.6（42.6） | 10:61 | 51.7 / 52.6（52.2） | 6:65 | 16:126 | 2e-22 |
| **gate（V0.15）** | 66.1 / 63.5（64.8） | — | 78.4 / 76.7（77.6） | — | — | — |
| gate+retry | 67.8 / 68.7（68.3） | 17:9 | 83.6 / 85.3（84.5） | 22:6 | 39:15 | 0.0015 |
| reranker 特征 + gate | 66.1 / 65.2（65.7） | 7:5 | 81.0 / 80.2（80.6） | 13:6 | 20:11 | 0.15 |
| **reranker 特征 + gate+retry** | **72.2 / 70.4（71.3）** | **19:4** | **86.2 / 86.2（86.2）** | **25:5** | **44:9** | **1.2e-6** |
| reranker 特征 + gate_fast（st=0.8） | 62.6 / 63.5（63.0） | 5:9 | 77.6 / 75.0（76.3） | 9:12 | 14:21 | 0.31 |

直接对比：
- reranker 特征 + gate+retry 对只加 gate+retry：11:4 + 8:4 = 19:8，p=0.052；
- 噪声对照：auto 两轮之间的差异不到 1 分。

### 成本（每题平均，两个 held-out 合并）

| 方案 | LLM 调用（选读 + 重试） | LLM 输入 token（含回答） | 美元 / 题 | 检索延迟 |
|---|---|---|---|---|
| auto | 0 | 10.4k | 0.0017 | 约 80 ms |
| gate | 1.00 | 14.4k | 0.0024 | 约 80 ms |
| gate+retry | 1.39～1.57 | 18.1k | 0.0030 | 约 80 ms |
| reranker 特征 + gate+retry | 1.33～1.58 | 18.1k | 0.0030 | 约 8～10 s* |
| reranker 特征 + gate_fast | 0.85～0.93 | 14.4k | 0.0023 | 约 8～10 s* |

\* 延迟是在 2 核机器上、8 个并发、同时还在做向量化的情况下测的墙钟时间，包含 MiniLM 对 30 个候选的打分；单独运行时短得多，见第 4 节。打分有缓存，同一问题的重复检索不会再算。

- 所有 retry 版本中，约 33～58% 的题触发了第二次检索（每次触发多 1 次选读调用和 1 次回答调用）。

## 3. 结论

1. **新的最优组合是 gate + MiniLM reranker 置信度特征 + 答案自检重试。** 在两个 held-out 上都是最高分：FinanceBench test 71.3，finx 86.2。对 V0.15 gate 合计 44:9（p=1.2e-6）。代价是每题平均 1.33～1.58 次 LLM 调用、约 4 秒 reranker 打分，以及约 25% 的额外 token 费用。
2. **答案自检重试是主要增益来源**（单独 39:15，p=0.0015）。它对应 Agentic RAG / Self-RAG 的“判断不足就再查”，但只在答案声明证据不足时触发，所以平均成本低。
3. **reranker 的正确用法是作为置信度特征，而不是替代排序。**
   - 单独使用时，准确率提升不显著（20:11），但置信度排序明显变准：MRR 0.61 → 0.67。
   - 它让第二次检索选得更准：对只用 retry 为 19:8，p=0.052。
   - 交叉编码器（33M / 278M）和 ColBERT 效果相当，模型变大没有收益。
4. **能跳过 LLM 的 gate_fast 在 held-out 上略差**（14:21），不推荐。省调用的版本仍然是 V0.15 的 G-skip。
5. **Evidence Search（含 MCTS）在本项目的数据上没有赢。**
   - 不调 LLM 的搜索在 FinanceBench 上与 auto 相当（34～37 对 40），低于一次 LLM 选读（gate 54）。
   - 在 longdoc 这类文字文档上，它能用 1/3 的 token 拿到同样的分数，补满预算后还略高（87.0 对 82.6）。
   - MCTS 只有在修复“沿访问最多路径停在浅层”的问题、并加上检索置信度先验之后，才追上 best-first。
   - 原因：
     - 财报题需要整张报表，而 MS MARCO 训练的 reranker 不擅长判断表格行与问题的相关性；
     - 奖励只是 reranker 分数的代理，并不是“能否答对”。
   - 这套框架保留下来；价值函数换成更强的判别器后可以重新评估。
6. **提示词优化没有收益。** 默认 guidance 已经接近 dev 上的上限。
7. **表格感知解析 + 上下文索引在 dev 上有明显收益**：所有 LLM 选读方案合计 20:6，gate 从 54.3 升到 71.4，gate+retry 从 71.4 升到 80.0。但还没有在 held-out 上验证，这是下一步的首要实验（构建 finx-tc，再跑 2 轮）。

## 4. 推荐配置

```python
pol = RetrievalPolicy(
    fusion="gate",
    rerank="ce:Xenova/ms-marco-MiniLM-L-12-v2", rerank_k=30,   # 置信度特征，不改排序
    context_budget=2000, context_policy="gate",
)
# 回答后，若答案声明证据不足：排除已读块，用 "retry" 规格再检索、再选读、再回答
# （benchmarks/run_qa.py 中的 +retry 是参考实现）
```

- 默认仍是 `auto`，零 LLM；默认路径与 V0.12 逐位一致（`regress.py` 结果为 SAME）。
- reranker 是可选依赖（fastembed）；没有安装时，可以去掉 `rerank`，其余不变。

## 5. 局限

- finx 只覆盖财报这一个领域，它和 FinanceBench 的题目风格相同。
- reranker 打分的墙钟延迟，是在 2 核、并发、同时向量化的环境下测的（30 个候选约 4 秒），没有在空闲机器上单独测；可以用 `rerank_k` 缩小打分范围来降低。
- 重试的触发条件是答案文本里出现“不足 / 无法确定”一类说法（正则），依赖回答模型愿意承认证据不足。
- 表格感知语料与上下文索引只在 FinanceBench dev 上比较过（见 1.4），两项一起开，没有分开消融；finx 的表格感知语料因为时间不够没有构建，所以没有进入 held-out。
