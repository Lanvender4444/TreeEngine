## 结论（回答执行计划第 11 节）

**Q1. FTS 和 Vector 应该等权吗？保持 1:1。**
- W1（降低 Vector 权重）：@2000 −1.1（2:4），@3000 +0.5（4:3）。candidate recall 从 96.2 降到 94.0（3 题变差，0 题变好）。
- W2（降低 FTS 权重）：@2000 −3.3（1:4），@3000 +2.7（5:1，p=0.22）。两档预算的方向相反，都不显著；candidate recall 从 96.2 降到 95.6。
- 两个偏置配置都没有显著优势，且都损失少量候选召回。按规则，不为 1–3 点的噪声引入额外的默认参数。

**Q2. Tree 作为第三路 signal，有没有稳定的正收益权重？没有。**
- 与 W0 相比：W3（0.25）为 −0.5 / +2.2，W4（0.5）为 −0.5 / +1.1，W5（1.0）为 −2.2 / +1.1（@2000 / @3000）。全部 p ≥ 0.125。@2000 三者都略差，@3000 三者都略好。
- 三个 Tree 权重之间的胜负都只有 0–2 题，不存在 “小权重最好” 或 “越大越好” 的趋势，属于执行计划第 7B 节的情况 1：全部无收益。
- **关键对照**：没有触发树推理的题，W3–W5 的候选列表和阅读上下文与 W0 完全相同，这部分题上的胜负只能是答题和判分的噪声。W3 @3000 的 +2.2（4:0）**全部来自没有触发树推理的题**；在触发树推理的题上是 0:0。也就是说，表面上的提升全是噪声，Tree 权重本身没有贡献。

**Q3. 收益来自哪里？** 来源不存在，具体看各层：
- **candidate recall**：在所有题上都没变（0:0），Tree 没有补回漏掉的证据。
- **排序**：recall@5 仅 +0.5（67.8 → 68.3），R@2k 在 W5 上 +0.6；只影响个别题的排位。
- **context selection**：coverage 只在 1–2 题上变化（W4 / W5），而且有升有降。
- **QA**：在触发树推理的题上，@3000 为 0:0，@2000 为 0:1 到 0:2（略差）。

**Q4. 值得额外的成本吗？不值得。**
- W3–W5 有三分之一的题会触发树推理，平均每题 0.5 次 LLM 调用、约 560 输入 + 20 输出 token。
- 检索延迟 p50 基本不变（约 27 ms），但 **p95 从约 60 ms 涨到约 2.2 s，增加约 37 倍**。
- 换来的准确率变化在噪声范围内。

**决策（执行计划第 10 节）**：6 条条件中，没有一个 Tree 权重满足 1（方向一致）、2（明确提升）、3（统计支持）、6（不是个别题驱动）。默认值保持：

```text
fts_weight = 1.0
vector_weight = 1.0
tree_weight = 0.0
agentic_level = 0.0
```

Tree Agent 继续作为可选 / 实验能力。没有配置明显更好，按计划不补第 3 次运行。

## 噪声提示

- 同一配置的两次运行之间，每档有 0–4 题改判（见 “Run-to-run noise” 表）。
- 上下文完全相同的题之间也会出现 4:0 的胜负，因为 temperature 0 的 API 输出也不完全确定。
- 所以本轮小于 5 点的差异都不做解读。

## 局限

- 只有 longdoc 一个数据集。它的 candidate recall 已经很高（96%），Tree 没有 “补证据” 的空间；要验证 Tree 能不能补证据，需要证据分散、检索词与原文不匹配的数据集。
- Embedding 是临时的 bge-small。
- Answer 和 Judge 是同一个模型。
